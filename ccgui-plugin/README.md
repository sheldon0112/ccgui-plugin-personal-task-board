# 个人任务看板

为 CC GUI 编写的本地 JavaScript 插件，参考 Multica 的任务分派与人工验收流程，使用宿主工作区、模型和原生会话，无额外数据库或后端。本插件未提取 Multica 的原版界面或业务代码。

## 当前筛选（0.1.9）

主工具栏只保留工作区、项目、搜索和清除筛选。快捷筛选仅保留全部、待修正、已逾期；待验收和受阻直接在状态列查看。

已移除优先级筛选、标签筛选和隐藏子任务开关：优先级仍可排序与批量修改，标签仍可编辑并通过搜索查找，子任务统一显示。旧视图中的这些条件不再参与筛选。布局在首页右侧直接切换；排序和命名视图在“视图设置”中。

以下版本功能说明中涉及旧筛选的部分，以本节为准。

## 安装与使用

在 CC GUI 的“插件 → 从本地目录安装”选择 `~/ccgui-plugins/personal-task-board/`（含 `manifest.json` 的那一层），安装后点击侧边栏“个人任务看板”。要求宿主支持 SDK 0.3.19 及以上，并具备原生会话执行接口。

点击“新建任务”或任务卡片的“编辑”后，会打开独立的“任务编辑”中央页签。保存或取消会返回看板，新建表单不会占用看板空间。各状态列等高占用页签剩余的可视区域，任务多时在列内滚动；点击状态列标题可分别折叠或展开，折叠后保留状态名和任务数量。

创建任务时填写标题、需求、验收标准和优先级，选择已登记工作区、已启用引擎与模型。模型留空时使用宿主默认模型。新增工作区或修改可用引擎后，点击“重新载入”。

需求和验收标准各有独立的“选择文件”按钮，可多次选择本地文件；重复选择同一文件会去重，可单独移除。两部分均可使用文字、附件或两者结合。保存的是原文件路径，执行时会话按路径读取；请保留原文件，原文件修改后下次执行会读取修改后的内容。任务卡片展开“需求与验收”后点击文件名，可在文件管理器中定位。移除附件只取消关联，不删除原文件。

0.1.1 新增 `assets:directory` 权限，用于宿主文件选择和授权；SDK 会为所选文件的父目录建立该插件的资源授权。没有上传到额外服务器，也没有加入外部命令权限。根据本轮确认，暂不扩展客户端；Finder 直接拖入需求区域的功能尚未接入。

模型目录包含 CLI、宿主默认、自定义和已配置渠道的模型；渠道模型以“模型 · 渠道”显示，执行时绑定所选渠道。读取目录和启动前检查可能需要等待宿主探测已启用的引擎，界面会显示加载状态；不会主动请求刷新供应商远程模型接口。

点击任务上的“开始执行”，会创建宿主原生会话；“打开会话”和执行记录中的“查看结果”均跳转到对应聊天，查看完整输出与工具调用。“停止执行”请求停止本任务的轮次，收到终态回执后收尾。执行失败进入“受阻”；正常结束或中断进入“待验收”，检查结果后手动点击“验收通过”。验收存在偏差时提交独立反馈后执行修正；调整原始清单时使用编辑。每次执行会保留独立记录。

同一时间只运行一项本插件任务。创建任务不会自动执行。提示词会要求 AI 报告验证结果并禁止自行提交、推送；AI 的文件与命令权限仍由宿主设置决定。

## 验收不通过与返工

在“待验收”任务中点击“验收不通过”，在独立反馈页填写具体的未通过项、实际偏差和修正要求，点击“保存反馈”。反馈会追加到该任务的独立记录中，原需求、原验收标准与原会话不变；任务回到待办并显示“验收未通过 · 待修正”。保存反馈不会自动启动 AI。

点击“执行修正”，原生会话会收到原任务、验收标准、原附件路径和所有尚未通过的反馈，并被要求保留已满足的行为、逐条报告验证结果。具备 SDK 0.3.23 续接能力且配置一致时追加到原会话；旧宿主创建新修正会话。历次会话仍可从执行记录中打开。修正结束后回到待验收，可继续反馈并多次返工。全部满足后点击“验收通过”，相关反馈才会显示“已通过复验”。

任务卡片的“验收反馈”保留每次反馈、时间和对应执行结果入口；“执行记录”标识任务执行或修正执行，以及该次是否验收通过。待修正任务可以“补充反馈”。“编辑”始终只调整原始任务清单，不会改写或删除已有反馈。

## 0.1.4 新增个人工作流

- **快捷筛选**：全部、待验收、待修正和异常，可叠加工作区与搜索。待修正只显示仍需启动修正的待办或受阻任务，不包含正在执行或已回到待验收的任务。
- **视图记忆**：自动保留工作区、搜索文字、快捷筛选和各列折叠状态，切换页签或重载插件后恢复。新增 `storage` 权限，仅保存本插件的轻量视图设置；任务仍使用独立的 `tasks.json`。
- **任务详情**：点击卡片标题，进入独立详情页，集中查看原需求、验收标准、附件、历次反馈和会话入口。
- **执行输入快照**：新执行会在启动前保存本轮提示词、工作区、引擎、模型和渠道。卡片执行记录点击“查看输入”或在详情页展开本轮输入即可核对；编辑原任务不会改写旧输入。旧版本运行显示“未记录输入快照”。快照记录提示词与配置，不复制附件内容；原附件仍可能变化。
- **反馈附件**：验收反馈页可选择截图或文件，可只附文件。附件独立归属于该条反馈，修正会话会收到所有未通过反馈及其附件路径；附件保留原文件，不存入额外服务器。

## 任务评论与 Agent 处理

点击卡片的“评论”或任务标题，在详情页的“任务评论”中讨论偏差。普通留言只保存；输入 `@Agent`，或点击某轮结果的“回复 Agent”后发送，会将该评论交给任务所选引擎和模型。回复已触发 Agent 的讨论也会沿用该路由。`/note` 开头、`@all` 或明确提及其他对象时不自动交给 Agent。

发送前显示本次是否触发。评论与附件先在本地保存，再启动原生会话；本轮输入单独标明“本轮重点评论”，附上原任务、历史讨论和历史会话标识，旧需求、评论及运行记录均保留。执行结束仍进入待验收，验收通过后标记相关评论已通过验收。附件只保存本地路径。

SDK 无法读取原生聊天的完整回复，讨论中的 Agent 条目显示执行状态和“查看 Agent 结果”入口，完整文本保留在原生会话中。回复时可点击“打开原会话继续”跳转查看。

0.1.6 支持增强宿主 SDK 0.3.23 的 `sessions.supportsResume` 能力：配置一致时，评论和验收返工续接已有原生会话；回复指定旧轮次时，续接该轮所属会话。首次执行、旧宿主没有能力标记、工作区/引擎/模型/渠道变更时创建新会话。续接目标丢失、读取失败或忙碌时保留评论并报错，不会静默新建替代会话。轮次仍分别记录输入快照与验收状态。

仍不支持运行中插话：忙碌时评论保存为待处理，结束后点击“交给 Agent 处理”。

## 0.1.6 十项个人功能

1. **标签**：编辑任务时用逗号分隔；视图工具中按标签筛选，搜索也覆盖标签。
2. **截止日期**：可选日期，卡片标注逾期，快捷筛选可集中查看未结束的逾期任务。
3. **父子任务**：表单可选父任务；详情中可创建、打开子任务并查看完成进度，父子各自验收。
4. **评论拆分**：已发布的个人评论可“拆为子任务”，先打开可编辑表单，保存后生成任务；保留当时的原任务和截至该评论的讨论快照，后续改动不覆盖来源。
5. **命名视图**：“视图与批量操作”中保存、选择及移除常用组合，包含工作区、搜索、标签、快捷筛选、排序和折叠状态。
6. **排序**：优先级、最近更新、创建时间、截止日期；没有截止日期的任务排在日期排序后面。
7. **评论草稿**：评论内容、回复目标和所选附件按任务保存在本机，切页或重新加载后恢复；发送成功才清空，保存失败保留。
8. **评论快捷操作**：为当前评论起名称保存为可复用操作，点击仅填入草稿，确认发送后才触发 Agent；可移除预设，已发表的评论保留。
9. **批量调整**：勾选卡片或选择当前筛选结果，批量改优先级、移回待办或取消。只作用于当前筛选内的选择；含运行中或待核对任务时整批拒绝，不支持批量验收完成。
10. **重复任务**：详情中指定原始任务，重复项转为取消且保留历史；原任务和重复项互相可跳转，“不是重复”恢复为待办。重复关系只允许一层，重复项不能启动执行。

视图工具默认折叠，展开后限高滚动，保持看板各列占用剩余可视区域。新增数据继续保存在插件本机隔离存储，无新增权限或后端。


## 0.1.7 第二批十项功能

1. **列表视图**：在视图工具中切换列表/看板，列表与看板共用同一批任务、选择、排序和筛选。
2. **项目**：任务可填个人项目名称；视图工具按项目筛选并汇总已结束/全部任务的比例。项目不是额外工作区，不改变执行目录。
3. **优先级筛选**：与工作区、项目、标签、搜索和状态组合使用。
4. **显示子任务**：取消后只显示父级任务，保存视图会记录这一选项。
5. **子任务阶段**：父子任务关联下可设置 1–999 的阶段，未设置视为阶段 1。较早阶段全部完成或取消后才能启动后续阶段；同阶段可逐项推进，仍遵守看板单运行限制。不会自动验收父任务。
6. **讨论解决**：个人评论或 Agent 结果条目的讨论可标记已解决并整体折叠；重新打开或继续回复会恢复显示。解决讨论不代表任务或验收通过。
7. **表情反馈**：个人评论可切换 👍 / ✅ / 👀，不触发 Agent，也不改变状态。
8. **引用评论**：引用整条评论的前 4000 字作为背景，单独填写偏差意见。发布时保存引用快照，触发只按新正文及回复路由判断，引用中的 `@Agent` 不被当成新提及。
9. **执行统计**：按当前筛选汇总真正启动并结束的运行次数、失败率和有效耗时。未启动尝试、缺失耗时、未知运行状态分开处理，不显示伪造的 token 或费用。
10. **附件汇总**：详情中按需求、验收、评论和反馈来源列出文件，可按图片、文档、视频、其他筛选。同一路径在多条评论关联时保留各自来源；这是本地关联汇总，不是文件版本存储或 AI 产物抓取。

## 0.1.8 筛选与对齐修复

视图工具的标签、下拉框、复选框和按钮统一垂直居中，修复“显示子任务”额外上边距。工具栏增加“清除筛选”，任务计数显示“当前可见 / 全部”；筛选隐藏所有任务时明确提示。

普通新任务默认继承当前工作区、项目、标签与优先级筛选。保存新任务或编辑任务后，只调整会隐藏该任务的筛选，并展开任务所在状态列；取消编辑不改变视图。任务本身的需求、项目与父子关系不会因为清除筛选而被修改。

## 数据与恢复

任务保存在 SDK `documentStorage` 默认的插件隔离目录中的 `tasks.json`，通过版本令牌进行条件写入，不使用浏览器存储。模型调用仍使用宿主配置，可能连接在线服务。

插件重载或应用重启后，未收到终态回执的任务会标记“运行状态待核对”，阻止重复执行。先打开会话核实状态，仍在运行时在聊天中停止；确认结束后点击“已核对会话结束”，进入待验收。SDK 没有运行状态查询接口，插件不会把重启前的记录当作实时运行状态，也不会自动重发任务。

读取失败、文件格式异常或保存冲突都会显示错误，不覆盖未知格式文件。存储问题修复后点击“重新载入”；如有运行任务，先结束它。会话标识可能稍后返回，在获得标识之前不能跳转；原始会话被移除后，跳转能否恢复由宿主决定。

## 更新与卸载

修改同一目录后，再次通过“从本地目录安装”安装相同 ID，宿主会热重载。更新前请结束看板任务。插件页可禁用或卸载；按宿主规则，卸载后的插件数据保留 30 天。插件停用不会主动中断宿主聊天，仍可在聊天界面停止。

## 验证

仓库中的 `ccgui-plugin-tests/board.test.mjs` 使用 Node 内置测试运行器覆盖存储、启动、停止、异常与恢复；`ui.test.mjs` 使用 CC GUI 开发仓库已有的 React、ReactDOM、jsdom 做真实组件挂载，不调用真实 AI。运行：

```sh
rtk proxy node --test ccgui-plugin-tests/*.test.mjs
```

组件测试默认从同级 `personal_desktop-cc-gui` 仓库加载依赖，其他位置可通过 `CCGUI_HOST_PACKAGE` 指定该开发仓库 `package.json` 的绝对路径。插件运行本身不需要这些测试依赖。


## 0.1.10 操作与验收效率

- 列表中可直接修改标题、优先级和截止日期。保存才写入；取消或 Esc 放弃本次修改，保存失败保留输入。执行中、运行状态待核对的任务不能编辑。
- 看板、列表的“预览”及甘特任务条打开侧边详情，不切走当前看板。支持上一项、下一项、方向键导航、Esc 关闭及完整详情入口；表单输入时不触发方向键导航。
- “执行通知”汇总历史及新增已结束、失败、中断和待核对轮次；支持已读、未读、归档与恢复。通知操作不代表任务验收通过，不改变执行状态；这是插件内通知，不是系统推送。
- 编辑任务可选开始日期，不能晚于截止日期。“视图与批量操作 → 布局 → 甘特时间轴”按自然日显示区间；只有单端日期时显示日期点，双端都没有时列入“未排期”。与看板、列表共用任务和筛选。

本轮不扩展宿主。交付物内容快照、真正历史文件版本及后台定时/条件唤醒尚未实现；继续使用现有附件汇总。后续需要宿主 SDK 提供授权文件快照与持久调度能力，不能用文件路径标签代替版本，也不能用页面计时器代替后台调度。


## 0.1.11 界面统一

列表快捷编辑、通知操作及预览导航统一为 30px 紧凑控件，采用 6px 操作间距。列表任务标题与操作分组排列，编辑表单保存/取消保持同高。通知分为任务标题、状态时间和操作组，宽屏横向排列，窄屏自动换行，通知区继续限高滚动。

侧边预览固定导航区，标题、分区标题与字段标题使用明确层级，长标题可换行，正文独立滚动。甘特任务条沿用状态配色，日期范围与背景轨道弱化；只有单端日期的任务用虚线边框区分，未排期任务集中紧凑展示。


## 0.1.12 卡片标题操作

看板卡片的预览按钮与任务标题同排并固定靠右，长标题在左侧换行。卡片勾选框用于批量选择：勾选任务后展开“视图与批量操作”，可统一调整优先级、移回待办或取消；勾选本身不执行、不完成任务。批量操作只作用于当前筛选中可见的已选任务，执行中或待核对任务不能勾选，验收通过仍需逐项确认。“选择筛选结果”选择当前可操作任务，“清空选择”取消全部勾选；切换布局时共享选择，重新加载插件后不保留。


## 0.1.13 卡片、快捷操作与父子泳道

- **精简卡片**：默认保留优先级、项目、截止日期及父任务。打开“视图与批量操作 → 卡片显示字段”可调整九个字段，设置随视图保存。任务标题、执行错误、待核对提示及验收操作始终保留；隐藏的需求和附件仍可在详情查看。
- **面板快捷键**：焦点在看板内时，`C` 新建任务、`/` 聚焦搜索；输入框、选择框、可编辑区域和中文组字期间不触发，带修饰键也不触发。预览中 `J` / `K` 或上下方向键切换，`Esc` 关闭。看板与列表中 Shift 点击标题打开预览，Shift 点击预览按钮打开完整详情。快捷操作不会执行或验收任务。
- **父子任务泳道**：“任务布局”选择“父子任务泳道”。按最顶层父任务分组，后代保留各自状态；没有父子关系的任务归入“独立任务”。泳道可折叠并保存，父任务入口可随时预览。沿用当前筛选和排序，筛选隐藏的父任务仅提供分组名称和入口，不额外展示其卡片。

更新时在 CC GUI“插件 → 从本地目录安装”重新选择 `~/ccgui-plugins/personal-task-board/`，同一 ID 热重载；插件页可禁用或卸载。


## 0.1.14 项目说明、通知批量与快捷操作管理

- **项目共享说明**：在“视图与批量操作 → 项目共享说明”展开对应项目填写。按工作区路径和项目名称区分，同名项目互不串用；每轮执行包含当时保存的说明，并写入该轮输入快照。清空并保存可移除说明。项目改名或更换工作区后需为新组合填写说明。
- **通知批量处理**：执行通知中可全部标为已读、归档已读通知、归档已结束任务通知（已完成或已取消）。范围是整个通知收件箱，不受任务筛选影响；已归档通知不参与批量处理。不会修改任务状态、验收决定或执行记录，归档后仍可逐条恢复。
- **快捷操作管理**：任务详情的“评论快捷操作”可编辑名称和正文、归档及恢复。旧操作默认可用；归档后不会出现在可用操作中。使用操作只填入评论草稿，确认发送后才按评论规则处理。保存失败保留输入和上一个已保存的操作，不触发 AI。

任务与项目说明保存在插件 `tasks.json`；快捷操作保存在本插件设置。均复用已有权限。更新仍从 `~/ccgui-plugins/personal-task-board/` 安装，同一 ID 热重载；可在插件页禁用或卸载。


## 0.1.15 阶段提醒与讨论整理

- **阶段提醒**：任务通知包含子任务阶段进度。前序阶段全部完成或取消后，提示下一阶段可开始；全部结束时显示完成/取消数量。每个未结束父任务只显示当前最晚完成阶段的提醒，不自动启动任务或验收。提醒按当前子任务状态生成，重新打开子任务或结束父任务后不再显示；同一子任务集合、阶段与状态组合复用已读和归档标记，修改标题不会重复提醒。它不是永久事件历史。
- **讨论结论**：回复上可选择“以此回复作为结论”。保留问题和结论，其他过程折叠；可重新打开或用其他回复替换结论。继续回复该讨论会清除结论并重新打开，不改变任务验收状态。Agent 条目仍只有状态和会话入口，不代表读取了完整 Agent 输出。
- **长讨论导航**：两条及以上评论/运行条目时显示“跳转到评论”。选择后展开目标所在的折叠内容、滚动并聚焦目标；不会发表留言或触发执行。

更新入口仍为 CC GUI“插件 → 从本地目录安装”，选择 `~/ccgui-plugins/personal-task-board/`；同一 ID 热重载。插件页可禁用或卸载。


## 0.1.16 列表操作与来源对照

- **列表显示列**：“视图与批量操作 → 列表显示列”可独立隐藏优先级、项目、截止日期和工作区，选择、任务、状态始终显示。设置随视图保存并可重载恢复，隐藏字段仍可在详情查看。
- **Shift 连选**：列表中先勾选一项，再按 Shift 勾选另一项，按当前可见顺序选中两者之间的可操作任务；取消勾选则取消该范围。跳过执行中和待核对任务，锚点被筛选隐藏时只处理目标；清空选择同时清空锚点。不批量执行或验收。
- **默认打开任务**：在视图工具中选择标题默认打开完整详情或侧边预览；看板和列表的 Shift 点击标题使用另一种方式。预览按钮仍默认预览，Shift 点击进入完整详情。
- **可读来源快照**：从评论拆出的任务按标题、原需求、原验收和原讨论展示快照；新拆分任务保存来源任务标识，提示已捕获文字与附件关联的变化，并可打开来源任务。重新指定父任务不会改变来源。旧快照缺少来源标识时只展示历史内容，不猜测来源；缺失或无法解析的来源有明确提示并保留原文。

来源对照不读取文件内容，也不把拆分之后新增的评论当作旧快照变化。更新仍从 `~/ccgui-plugins/personal-task-board/` 安装相同 ID；插件页可禁用或卸载。


## 0.1.17 工具栏上移与历史轮次重试

- **布局**：标题下依次为工作区/项目/搜索栏、快捷筛选、任务通知、视图工具和任务区。通知展开后，筛选与搜索仍位于其上方。
- **历史轮次重试**：在任务详情“历次执行与输入”中，失败或中断轮次可展开“按此轮输入重试”。核对原提示词、工作区、引擎、模型及渠道后，点击“确认按历史输入重试”才执行。缺少输入快照的旧轮次不能重试。
- 重试固定使用历史提示词和配置创建新会话，记录来源轮次，不覆盖任务当前配置或旧记录。默认模型留空时仍由宿主使用当前默认值；原路径附件读取当前内容。之后新增的需求和反馈不会进入该历史输入。
- 同样遵守单任务运行、阶段、重复任务及配置有效性检查；写入成功后才启动。完成后停在待验收，未包含的新增反馈不能被此次重试验收通过。已完成/取消任务需先移回待办。

本轮不包含自动重试或后台执行。更新从 `~/ccgui-plugins/personal-task-board/` 安装同一 ID，插件页可禁用或卸载。


## 0.1.18 选区引用与来源定位

- 在任务详情的需求、验收标准或已发布个人评论中选中文字（鼠标或键盘选择），点击“加入评论引用”。引用进入本任务草稿并聚焦评论框，原有正文与附件保留。已有引用时按钮显示“替换评论引用”；每条评论保留一处引用，最多 4000 个字符，跨多个内容区域的选区不接受。
- 需求/验收引用作为新评论，清空之前的回复目标；评论引用回复到其来源评论。发送前可查看触发预览，只有新正文及回复路由决定是否触发 Agent，引用中的提及不作为新提及。
- 选区文字在加入草稿时保存快照，切页和重载后恢复；发送失败保留草稿，发送成功才清空。发布后显示来源类型与“查看引用来源”，可展开原评论所在讨论、滚动并聚焦来源；原文变化或来源不可用时提示并保留引用快照。
- 原有整条评论引用继续保留；原生 Agent 会话完整输出不可直接选区引用，本插件中的 Agent 状态条目也不提供此入口。

更新仍从 `~/ccgui-plugins/personal-task-board/` 安装同一 ID，插件页可禁用或卸载。没有新增权限。


## 任务面板配置

点击首页右下角“任务面板配置”，统一管理 Agent 成员、共享方法库、手动协调小队、视图偏好、项目共享说明与公共资源。保存后返回任务面板即可使用；配置页沿用原有存储。

配置页左侧按 Agent 成员、手动协调小队、共享方法库、项目说明与资源、视图偏好分类；协作配置在右侧列表选中后编辑。分类切换保留当前页面草稿，离开配置页前请保存所需修改。

每位 Agent 可在“成员头像”中选择独立图标，保存后显示在成员列表、任务负责人、评论和执行历史中。旧成员使用默认机器人；历史轮次保留当时的头像。头像为本地内置图标，无需上传图片。
