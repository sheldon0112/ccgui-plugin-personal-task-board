# 0.1.2 页面与看板布局验证

日期：2026-10-28。插件：`personal-task-board`。

## 最终实现

- 新建和编辑任务在独立的“任务编辑”中央页签中进行，不向看板页面插入表单。
- 保存成功或取消后返回看板；保存失败停留在编辑页并保留输入。
- 状态列等高填满当前页签扣除标题、筛选区和页脚后的可视区域，不按最长任务列表撑高整页。
- 每列任务列表单独垂直滚动；整行仍可横向滚动。
- 点击各状态列标题可分别折叠为 48px 窄条，保留状态、数量及展开入口。折叠只隐藏内容，不删除任务。

21 个测试通过，0 失败、0 跳过。UI 测试通过模拟宿主中央页签路由来挂载实际 React 组件，覆盖：

- 新建与编辑打开独立页签，看板不包含表单。
- 保存成功返回看板，保存失败保留原页面和输入。
- 取消返回看板，再次新建时不会沿用上次任务内容。
- 已有附件、模型选择与统一控件样式正常。
- 看板使用固定可视区域与列内滚动样式，不保留 560px 的硬性最小列高。
- 折叠状态与可访问属性正确，其他列不受影响，展开后内容恢复。

计算样式与组件测试不等同于真实浏览器布局测量。

## 实机进度

在本机 CC GUI 中已验证独立编辑页：新建打开“任务编辑”页签；取消返回原看板且任务数保持 3；编辑可回显已有附件与模型，保存后返回看板。

最初按最长一列撑高的版本已经废弃，最终实现采用可视区域高度、列内滚动和独立折叠。用户解锁 Mac 后，已通过“从本地目录安装”完成最终热更新，并在原生客户端验证通过：

- 同一行各状态列顶部、底部对齐，限制在页签可视区域内，页头、筛选区及页脚均可见。
- 在“已完成”列内滚动时，任务内容移动，列标题、其他列、页头与页脚位置不变。
- 分别折叠待办、执行中、受阻和已取消列，显示窄条、状态名、数量及展开入口，其他列正常显示。
- 折叠含有任务的“已完成”列后，任务卡片隐藏；展开后 3 项任务恢复显示，总任务数保持为 3。
- 最终安装文件与开发源码、本地安装来源逐字节一致；插件处于已启用、未隔离、无加载错误状态。
