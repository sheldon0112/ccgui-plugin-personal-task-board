## 真实客户端端到端验证

用户明确授权由助手完成自动化验证后，通过原生 UI 操作执行以下流程，使用独立工作区 `/private/tmp/ccgui-task-board.FmQSLp`，与业务仓库隔离。

1. **创建及编辑任务**：输入中文标题、需求与验收标准，选择临时工作区、Codex 引擎和明确模型 `gpt-6-sol`，保存成功。
2. **正常执行**：“自动化验收：原生会话与本地保存”要求直接返回 `CCGUI_TASK_BOARD_OK`，不执行命令或读写文件。原生聊天实际回复包含该标记，聊天展示模型 `gpt-6-sol`，耗时 17.9 秒。收到终态后看板进入待验收，未自动完成。
3. **结果跳转**：通过任务卡片“打开会话”进入相应原生聊天，核实提示词与结果，不是通过旁路直接启动 CLI。
4. **人工验收**：助手依据测试任务验收标准点击“验收通过”，任务进入已完成。
5. **真实停止**：“自动化验收：停止执行”仅要求运行 `sleep 60`。聊天中出现对应命令调用后，通过看板“停止执行”中断，任务进入待验收，执行记录结果为 `stopped`。测试标准确认后手动验收。
6. **持久化及热重载**：重新载入看板，并通过相同目录重新安装触发插件热重载，两个任务、所选模型、会话关联和执行记录均保留。最终界面显示已完成 2、执行中 0、待验收 0、受阻 0。
7. **安装一致性**：宿主安装文件与交付源码完全一致，安装记录 `enabled=true`、`quarantined=false`、`lastError=null`。

两项已完成测试任务及对应原生会话保留，便于用户查看证据。临时工作区中仅观察到宿主创建的 `.ccgui` 目录；测试未产生业务代码文件。

## 实测发现并修复

- 基础 CLI 模型列表未包含所有已配置模型，改用 SDK 聚合模型目录，纳入默认、自定义和渠道模型；渠道模型使用明确 providerId。
- 终态保存失败时，重新载入入口曾可能因旧执行状态而禁用，已按实际运行归属判断是否允许恢复，并补充回归测试。
- 已验收任务不再显示“等待验收”，历史记录仅描述执行结果；增加启动前模型检查的状态提示。

## 验证边界

- 真实模型调用验证了本机 Codex + `gpt-6-sol`；其他引擎、其他渠道、Windows/Linux 尚未实机验证。
- 损坏文件、磁盘错误、保存冲突和重启时仍有执行等场景使用自动化模拟验证，未人为破坏本机实际任务文件或在真实运行中强制关闭应用。
- 实际验证了插件热重载，没有重启整个 CC GUI，以免影响已有工作会话。
- SDK 无运行状态查询接口，重载后遗留执行必须打开会话核对；无法宣称自动恢复实时运行状态。
- 模型聚合可能探测多个已启用引擎，读取时有等待；插件显示加载提示，不主动刷新供应商远程模型接口。
