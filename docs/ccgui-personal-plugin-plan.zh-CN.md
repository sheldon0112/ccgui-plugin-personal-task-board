# Multica 个人 CC GUI 插件改造方案

分析日期：2026-10-28。源码基线：`48df977`（浅克隆，包含当前版本完整源码，不含完整提交历史）。

## 结论与假设

建议制作“个人任务看板”JavaScript 插件：保留 Multica 的任务分派与人工验收流程，使用 CC GUI 的工作区、模型和聊天会话执行任务。第一版无需部署 Multica 后端、数据库或守护进程。

这是基于 Multica 工作流程的精简适配，需要重新实现插件界面和本地任务管理；不是把原版网页直接打包为插件。假设使用者只有本人、任务主要对应本机代码仓库、希望在 CC GUI 中查看和接管 AI 执行。

首版现已实现并安装到本机 CC GUI；实现位于 `ccgui-plugin/`，自动化测试位于 `ccgui-plugin-tests/`。实际交付与验证记录见 [验收报告](ccgui-personal-plugin-validation.zh-CN.md)。下文保留设计依据，具体行为以插件说明和验收报告为准。

## 仓库分析依据

| 源码位置 | 作用 | 对改造的影响 |
| --- | --- | --- |
| `packages/views/issues/components/board-view.tsx` | 看板，使用拖拽、工作区、字段、项目与工作流查询 | 不是独立组件，直接移植会带入大量依赖 |
| `packages/core/issues/queries.ts` | 任务查询，经 API 获取任务与执行记录 | 仅复制界面无法获得本地任务管理能力 |
| `packages/core/issues/config/status.ts` | 内置状态及生命周期分类 | 可参考任务流转语义，个人版使用固定状态即可 |
| `packages/core/types/issue.ts` | 任务、优先级、人员/Agent/团队分派等类型 | 个人版只保留必要字段 |
| `packages/ui/`、`packages/views/package.json` | 原版组件与依赖 | 使用宿主 React 重建小型界面比搬入整个组件体系更直接 |
| `server/internal/service/`、`server/internal/scheduler/` | 后端业务与调度 | 原版自动分派并非纯前端能力 |
| `SELF_HOSTING.md` | Next.js、Go、PostgreSQL、CLI daemon 部署 | 保留完整产品需要持续运行额外服务 |

本机已检测到 `/Applications/CC GUI.app`，应用版本 `1.1.8`，以及 `~/.ccgui-next/plugins/` 插件目录。接口依据为插件技能中的 SDK `0.3.22` 文档，并参考本机 CC GUI 源码的 `session-run-bridge.ts`；尚未在已安装应用中验证这些接口，不能仅凭应用版本保证兼容。

## 方案比较

| 方案 | 优点 | 成本与限制 | 建议 |
| --- | --- | --- | --- |
| 原生个人看板插件 | 本地保存、复用 CC GUI 模型与会话、安装简单 | 需要重写精简界面，不包含原版所有能力 | 首选 |
| 插件接入完整 Multica 服务 | 保留原版任务、团队、调度体系 | 要维护后端、数据库、认证与 daemon；内嵌网页可行性还需验证 | 需要完整产品时再考虑 |
| 整体移植原版到插件 | 可尝试复用部分原版代码 | 原版框架和服务依赖与单文件插件契约差异大，改造范围最大 | 不作为个人版起点 |

## 第一版的具体使用流程

1. 从 CC GUI 侧边栏进入“个人任务看板”，在中央页签查看任务。
2. 选择已登记工作区，创建标题、描述、验收标准和优先级。
3. 选择宿主提供的可用引擎和模型，点击“开始执行”。插件将任务与验收标准组成提示词，调用宿主会话。
4. 任务卡片提供“打开会话”和“停止执行”；完整输出、工具调用及权限交互由原生聊天界面承载。
5. 运行结束后进入“待验收”；本人查看结果后手动标记“已完成”，或修改要求后重新执行。

固定状态为“待办、执行中、待验收、受阻、已完成、已取消”。技术错误进入“受阻”；停止操作单独记录，不把宿主 `done` 当作成功证据。第一版只允许一个由本插件发起的任务同时执行，避免在同一仓库并行修改文件；不妨碍用户正常使用其他会话。

暂不纳入第一版：多人协作、团队 Agent、自动拆分任务、自动调度、远程运行节点、定时任务、费用统计、自动提交或合并、完整执行日志复制、自定义工作流以及原版富文本编辑器。任务内容先使用普通文本，状态通过按钮切换。

## 最小实现与权限

插件目录建议为 `~/ccgui-plugins/personal-task-board/`，包含 `manifest.json`、自包含 ESM `main.js`，以及中文说明。入口为 `export default function activate(ctx)`，无 import、JSX 或直接 Tauri 调用。

| 能力 | SDK 接口 | 所需权限 |
| --- | --- | --- |
| 侧边栏入口 | `ui.registerSidebarNav` | `ui:sidebar-entry` |
| 中央看板 | `ui.registerCenterTab`、`ui.openCenterTab` | `ui:center-tab` |
| 工作区选择 | `workspaces.list` | `host:workspace` |
| 可用引擎与模型 | `models.listEngines`、`models.catalog` | `host:models` |
| 执行、停止、打开会话 | `sessions.startRun`、`sessions.interruptRun`、`sessions.selectSession` | `host:session` |
| 接收运行回执 | `events.on` | `events` |
| 保存任务 | `documentStorage.readText`、`documentStorage.writeTextAtomic` | `plugin.storage` |

第一版不额外申请网络或外部命令权限。AI 执行仍通过宿主已有引擎及其权限机制，可能使用宿主配置的在线模型；“本地保存任务”不代表模型推理离线。

任务文档使用插件隔离存储，通过版本令牌进行条件写入。每项任务包含标识、标题、描述、验收标准、优先级、工作区路径、状态、时间及历次执行关联（引擎、模型、runId、sessionId、结果/错误）。保留每次执行关联，避免重试后丢失旧会话入口。

## 必须处理的边界

- **运行结束不等于验收通过**：SDK 明确说明中断也可能产生 `done`，始终保留人工验收。
- **会话标识可能稍后才出现**：启动返回的 sessionId 可以为空；依据宿主实际支持的后续回执补齐，在补齐前禁用“打开会话”。本机源码还包含 `started`、`session` 回执，需以已安装应用实测为准。
- **启动与终态回执可能先于 Promise 返回**：执行实现需验证快速完成与启动失败的事件顺序，避免任务永久停在执行中。
- **重启或热重载后回执可能丢失**：目前所读 SDK 没有运行状态查询接口。保存中的执行状态只能作为上次记录；重载后提示核对关联会话，由用户确认，不伪造实时状态或自动再次执行。
- **存储失败必须可见**：执行前先保存任务；保存失败时不启动 AI。存储版本冲突提示重新载入，避免静默覆盖。
- **错误与停止可追溯**：保留错误信息、停止请求和会话链接；停止失败要显示原因。

## 实施顺序与验收

1. 核实已安装客户端的 SDK 和加载契约，再制作最小中央页签。验收：安装后可从侧边栏打开，禁用后入口消失，应用无插件错误。
2. 实现任务创建、编辑、状态切换与保存。验收：重启后内容保留，不同工作区任务可区分，保存失败有明确反馈。
3. 接入模型选择和原生执行会话。验收：一次点击只启动一次；能够打开对应会话；启动失败、执行错误、中断和快速完成都有正确状态；重试保留旧执行记录。
4. 验证人工验收和重载行为。验收：AI 结束不自动完成任务；重载后不会误启动任务；用户可核对并修正记录状态。
5. 在本机 CC GUI 完成实际安装验收。涉及真实 AI 调用的验证应使用明确指定的无副作用任务，并遵守仓库关于真实 Agent 测试的授权要求。

最终安装通过 CC GUI 侧边栏“插件 → 从本地目录安装”，选择含 manifest 的目录。相同插件 ID 再次安装用于更新并热重载；卸载通过插件页执行，按宿主规则数据保留 30 天。不能以单纯复制文件替代安装成功的验证。
